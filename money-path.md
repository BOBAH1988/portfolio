# Денежный путь (Money-Path) — PWA для личных финансов

**Демо:** [BOBAH1988.github.io/Money-Path](https://BOBAH1988.github.io/Money-Path/) · **Репозиторий:** [BOBAH1988/Money-Path](https://github.com/BOBAH1988/Money-Path)

**Стек:** React 19, TypeScript, Vite, Firebase Authentication, Cloud Firestore,
React Router 7, Zod

## Задача

Собрать в одном приложении повседневный учёт личных финансов: планировать
бюджет, фиксировать доходы и расходы, вести активы и обязательства и
просматривать историю доходов. Приложение должно оставаться доступным
офлайн, а синхронизация между устройствами — быть необязательной.

## Решение

Money-Path — клиентское PWA. Гостевой режим хранит данные локально в
браузере; вход в аккаунт Firebase добавляет облачную синхронизацию.
Интерфейс и локально сохранённые данные доступны без постоянного
подключения к сети.

### Возможности

- **Бюджет:** плановые и фактические расходы, ежемесячные и дополнительные
  категории, автоматический пересчёт итогов; правка значений и названий
  прямо в ячейке (Enter — сохранить, Escape — отмена).
- **Активы, обязательства, доходы:** таблицы с правкой в ячейке,
  добавление кнопкой «+», удаление кнопкой «−» с подтверждением.
- **Дашборд:** доходы за месяц, средний доход, «осталось оплатить» и чистый
  капитал; «Баланс месяца» делит доход на оплаченное и оставшееся со шкалой
  и процентом оплаты; архив доходов по месяцам с выбором года.
- **Импорт и экспорт:** JSON-архив с проверкой перед восстановлением.
- **Офлайн-работа:** локальный кэш, очередь неотправленных изменений,
  Service Worker и страница «Нет подключения».
- **Аккаунт:** вход по email и паролю, восстановление доступа, подтверждение
  адреса, удаление аккаунта с 7-дневным периодом отмены.
- **PWA:** установка на устройство, светлая и тёмная темы, проверка
  обновлений из меню.
- **Служебные страницы:** инструкция, условия использования, уведомление
  о конфиденциальности.

## Технические решения

- **React 19 и TypeScript** — интерфейс и типизированная логика приложения;
  маршрутизация — React Router 7 на `HashRouter` (`/#/budget`), чтобы
  подпуть GitHub Pages работал без серверных правил.
- **Vite** — локальная разработка и production-сборка для GitHub Pages
  (`base: '/Money-Path/'`).
- **Firebase Authentication и Cloud Firestore** — аккаунты и хранение
  данных пользователей в `users/{uid}/{collection}`. Параметры проекта
  передаются через `VITE_FIREBASE_*`, в исходном коде ключа нет.
- **Zod** — валидация данных, включая схему импорта архива.
- **Ваш пароль проверяется строго:** 10–128 символов, заглавная и строчная
  буквы, цифра, спецсимвол, проверка по списку распространённых паролей
  и повторяющихся фрагментов (`src/lib/validation.ts`).
- **localStorage, IndexedDB и Service Worker** — локальные данные, очередь
  синхронизации и кэш приложения. Конфликты решаются по правилу «побеждает
  последнее успешно синхронизированное изменение записи» — это не журнал
  версий и не слияние полей.
- **Правила доступа** в `firestore.rules`: владельцу — только `users/{uid}`,
  администратору — чтение списка профилей, корневые коллекции закрыты.
- **Vitest, Testing Library и jsdom** — 132 теста в 20 файлах: юнит-тесты
  логики, компонентные и клик-тесты страниц; Firebase Emulator Suite
  используется для тестов правил Firestore (нужен Java 21+).
- **Ограничение API-ключа** — ключ веб-приложения публичен, поэтому
  в Google Cloud Console он ограничивается по HTTP referrer (для GitHub Pages
  нужны оба адреса — `https://<user>.github.io/*` и `/<repo>/*`) и списку API.
- **Импорт и экспорт JSON** — пользователь может перенести данные или
  восстановить их из резервной копии.

## Инженерные практики

- **Единая проверка перед публикацией:** `npm run check` = oxlint → тесты →
  проверка TypeScript и production-сборка; в CI — тот же порядок плюс тесты
  правил Firestore на эмуляторе.
- **Версия под контролем:** `package.json` как единственный источник версии,
  pre-commit hook увеличивает patch и синхронизирует `package-lock.json`.
- **Документация рядом с кодом:** `docs/operations.md` (деплой, мониторинг,
  резервные копии, инциденты), `docs/security.md` (зависимости и ограничения
  ключа), `docs/data-model.md`, `docs/import-spec.md`, `docs/incident-log.md`,
  `docs/workflow.md`, плюс `CHANGELOG.md`.
- **Диагностика по симптомам:** таблица «симптом → что проверить» покрывает
  отказ входа по referrer, несинхронизированные записи, пустую страницу на
  GitHub Pages и отсутствие офлайна при первом запуске.
- **Безопасность данных в обращениях:** финансовые данные, пароли и токены
  не попадают в issue, логи CI и сообщения об ошибках.

## Что показывает этот проект

- Проектирование клиентского приложения с локальным режимом и облачной
  синхронизацией, где офлайн — основной сценарий, а не аварийный.
- Учёт офлайн-сценариев и сохранение изменений до восстановления сети.
- Работу с Firebase Authentication, Firestore и правилами доступа,
  включая тесты правил на эмуляторе.
- Разработку и публикацию устанавливаемого PWA на GitHub Pages с
  ограничением ключа по домену.

Приложение предназначено для учёта и планирования и не является финансовой
или инвестиционной рекомендацией. Перед массовым импортом или изменениями
данных рекомендуется создать резервную копию.
