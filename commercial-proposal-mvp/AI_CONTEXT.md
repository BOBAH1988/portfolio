## 1. Назначение

Проект — демонстрационный статический веб-прототип.

Пользователь — менеджер по продажам.

Задача — добавить выбранный товар в черновик коммерческого предложения: выбрать товар из каталога, нажать «Добавить в КП», ввести количество и увидеть основные данные товара, цену, единицу измерения, сумму и статус позиции.

Проект демонстрирует продуктовый подход, базовую работу с AI-агентом, HTML/CSS/JavaScript и локальный Git.

Всё касается только условных демо-данных. Реальные товары, цены, бренды, лица, API, интеграции и коммерческие данные отсутствуют.

## 3. Основной сценарий MVP

1. Менеджер открывает `index.html` в браузере.
2. В каталоге выбирает демонстрационный товар.
3. Нажимает «Добавить в КП».
4. Инструмент добавляет товар в строку черновика.
5. Менеджер вводит количество.
6. Инструмент проверяет значение и показывает сумму или inline-ошибку.
7. Менеджер видит строку черновика с артикулом, наименованием, ценой, единицей измерения, количеством, суммой и статусом.
8. При вводе невалидного значения сумма становится «—», а статус становится ошибкой.
9. При вводе валидного положительного значения статус становится «готово».
10. При повторном добавлении того же товара по `id` не создаётся вторая строка.

## 4. Обязательные сценарии AC-01—AC-05

Сценарии вручную проверены в браузере и зафиксированы в `test-cases.md`.

- `AC-01`: Готово: вручную проверено в браузере. Новая строка черновика показывает артикул, наименование, цену, единицу измерения, поле количества, сумму и статус.
- `AC-02`: Готово: вручную проверено в браузере. Для цены 25 000 и количества 3 сумма показывается как `75 000`; после добавления второго товара значение остаётся в первой строке.
- `AC-03`: Готово: вручную проверено в браузере. `""`, `"0"`, `"-1"` и `"abc"` показывают ошибку и сумму `—`.
- `AC-04`: Готово: вручную проверено в браузере. Товар без цены добавляется, цена и сумма показывают `—`, статус показывает предупреждение.
- `AC-05`: Готово: вручную проверено в браузере. Повторное добавление определяется по `product.id` и не создаёт вторую строку.

При ручной проверке подтверждены: добавление строки; расчёт 25 000 × 3 = `75 000`; пустое, нулевое, отрицательное и текстовое количество; товар без цены; дубликат; сохранение состояния первой строки после добавления второй; выравнивание на широком и узком экране.

## 5. Принятые технические решения

- Стек: HTML5, CSS, чистый JavaScript.
- Фреймворки, npm, Node.js, TypeScript и сборщики не используются.
- Внешние библиотеки, CDN, изображения, шрифты и сетевые вызовы не используются.
- Демо-каталог хранится локально в массиве `PRODUCTS` в `app.js`.
- У каждого демо-товара есть стабильный уникальный `id`.
- Дубликаты проверяются только по `product.id`.
- Поле количества — `type="text"` с `inputmode="numeric"`.
- Валидация выполняется вручную по исходному `input.value`, единая функция `applyQuantityState(entry, refs)` — один источник правды для статуса, суммы и сообщения.
- Валидное количество — строка, состоящая только из цифр и представляющая положительное целое число.
- При вводе количества сумма пересчитывается по веткам: невалидное значение — сумма `—`, валидное значение — пересчёт. Старое корректное значение не остаётся на экране.
- Товар без цены использует `price: null`, добавляется в черновик, цена и сумма отображаются как `—`, статус показывает предупреждение.
- Цена и сумма форматируются вручную через обычный пробел U+0020: `25 000`, `75 000`.
- Рубль, копейки, запятые и неразрывные пробелы не используются.
- Черновик хранится только в памяти текущей страницы, без `localStorage`, `sessionStorage`, IndexedDB и cookies.
- Уведомления отображаются inline как `notification-message`.
- Для пользовательского текста используется `textContent`, без `innerHTML` с инъекцией.
- При вводе невалидного значения сумма мгновенно становится `—` и не остаётся прежней.
- `render()` пересоздаёт строки черновика, значения полей сохраняются через массив `draft[]`.

## 8. Правила работы с Git

Разрешено локально:

- `git status`, `git diff`, `git log`, `git show`;
- `git branch`, `git switch`, `git checkout`;
- `git add` (только явный список файлов, без `git add -A`);
- `git restore`, `git commit`.

Запрещено без отдельного явного запроса пользователя:

- `git push`, `git pull`, `git fetch`, `git clone`;
- `git reset --hard`, `git clean -fd`;
- `git rebase`, `git merge`, `git branch -D`;
- удаление тегов и веток.

Порядок коммита:

1. Показать `git status`.
2. Показать `git diff --cached`.
3. Показать список файлов и предлагаемый текст коммита.
4. Дождаться явного подтверждения пользователя.
5. Выполнить `git add` по явному списку файлов и `git commit`.
6. Показать хеш коммита и `git status` после него.

После коммита показать: хеш, `git status`, краткий список файлов. Push не выполнять никогда без отдельного прямого запроса.

Если `index.lock` мешает локальной операции и ни один git-процесс не запущен — удалить его вручную через `rm -f .git/index.lock`.

## 9. Протокол работы AI-агента

1. Прочитать этот файл целиком.
2. Прочитать только файлы, связанные с текущей задачей.
3. Выполнить `git status` и зафиксировать исходное состояние.
4. Сначала показать план и список изменяемых файлов.
5. Дождаться подтверждения пользователя до любых правок.
6. Внести минимально необходимые изменения.
7. Выполнить доступную локальную проверку или выдать ручной чек-лист.
8. Показать `git diff` только по изменённым файлам.
9. Не выполнять `git add`/`git commit` без отдельного подтверждения.
10. Не выполнять `git push`/`git pull`/`git fetch` без отдельного прямого запроса.

- Нет внешних подключений и сетевых вызовов.
- Нет браузерного хранилища и браузерных диалогов.
- Поле количества — `type="text"`, не `type="number"`.
- Дубликаты проверяются по `product.id`.
- Для `""`, `"0"`, `"-1"`, `"abc"` показана inline-ошибка, сумма `—`.

- Код и документы не противоречат друг другу.
