# mail-automation — автоматизация почтовых процессов

**Стек:** Python, IMAP/SMTP, openpyxl, xlrd, GitHub Actions, concurrent.futures  
**Репозиторий:** приватный (по запросу)

## Задача

В B2B-опте ежедневно требовалось:
- рассылать прайс-листы клиентам (вручную — часы работы);
- пересылать заказы и счета оператору и клиентам;
- отвечать на запросы по дебиторской задолженности;
- формировать KPI-отчёты для руководства.

Всё это делалось вручную, с ошибками и задержками.

## Решение

Построил систему из **12 автоматизированных проектов** на GitHub Actions. 
Каждый проект решает свою задачу и запускается по расписанию в облаке — 
без включённого компьютера и участия человека.

### Что автоматизировано

| Проект | Задача | Расписание |
|---|---|---|
| Лемур / Прусакова | Рассылка прайса + напоминания поставщику | Пн, пт |
| Ухта | Рассылка прайса + удаление служебных строк | Пн, вт |
| Сети Ухта | Разовая рассылка готового прайса | Пн |
| Заказ Прусакова | Пересылка заказа оператору + классификация писем | Пн |
| Счёт Прусакова | Пересылка счёта клиенту | Ср |
| Счета в Велес | Пересылка счетов контрагенту | Ср |
| Ответ по ДЗ | Анализ файла дебиторки + ответ | Пт |
| Счёт ВЕТА ООО | Пересылка счёта клиенту | Пн |
| Счета клиентам | Массовая пересылка по списку | Пн, вт |

### Архитектура

- **Диспетчер** `run_all.py` — единая точка расписания (`JOBS`), 
  параллельный запуск до 4 проектов через `ThreadPoolExecutor`.
- **Общие модули:** `mail_common.py` (IMAP/SMTP), `price_processor.py` 
  (обработка Excel), `send_email.py`, `notify.py`, `constants.py`.
- **Обработка ошибок:** retry только для транзиторных сетевых сбоев; 
  ошибки аутентификации не ретраятся (защита от блокировки).
- **Логирование:** структурированное, с временем МСК.
- **Аварийный канал:** при сбое обработки — письмо «❌ Ошибка» на личный email.

### Тестирование

- **98 сценариев** в `tests/scenarios.py` — прогон всех проектов 
  на заглушках IMAP/SMTP без выхода в сеть.
- **Автопрогон в CI** при каждом push.
- Проверка «до/после» при рефакторинге — расхождений быть не должно.

### Результаты

- **Экономия до 10 часов в неделю** на рутинных операциях.
- Исключены ошибки ручной обработки (забыл письмо, не тот файл, дубль).
- Работает в облаке, не требует включённого компьютера.
- Масштабируется: добавление нового проекта — 30–60 минут.

### Инженерные решения под ограничения

- **Компенсация задержек GitHub Actions:** утренние слоты сдвинуты 
  на 3 часа раньше — при задержке 3–4 ч исполнение попадает в окно.
- **Защита от дублей:** проверка папки «Отправленные» перед рассылкой.
- **Тестовый режим:** при ручном запуске можно прогнать на себя, 
  не беспокоя клиентов.
- **Локаль-независимая дата в IMAP SEARCH:** месяц всегда английский.
- **Приватность:** BCC-рассылка — клиенты не видят друг друга.
